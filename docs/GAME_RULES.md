# 기억 포커 게임 규칙 (확정본)

데블스플랜 3: 데드 어게인의 "기억 포커"를 바탕으로 한 규칙. 이 문서가 구현의 기준이다.

## 1. 구성

- 표준 52장 덱 (조커 없음)
- **기억 카드 16장**: 4x4 보드에 놓이는 서로 다른 카드 16장
  - 각 칸은 `A`~`P` 문자와 `1`~`16` 번호로 라벨링 (A=1, B=2, …, P=16)
  - 코드 내부의 칸 인덱스는 0부터 시작한다 (A=0, B=1, …, P=15). 화면 표시용 번호(1~16)와 구분한다.
  - 배치 순서: 왼쪽 위부터 행 우선 (1행: A B C D, 2행: E F G H, 3행: I J K L, 4행: M N O P)
- **공유 카드 3장**: 기억 카드 16장과 겹치지 않는 카드 3장
- 기억 카드와 공유 카드는 한 덱에서 함께 뽑아 총 19장이 모두 서로 다르다.

## 2. 진행 (1대1, 현재는 플레이어 vs 컴퓨터)

1. **암기 단계 (60초)**: 16장의 앞면을 모두 공개한다. 공유 카드는 아직 보여주지 않는다.
2. **뒤집기**: 60초가 지나면 16장을 모두 뒷면으로 뒤집는다.
3. **공유 카드 공개**: 뒤집은 다음 공유 카드 3장을 공개한다.
4. **선택 단계 (30초)**: 각 플레이어가 기억에 의존해 16칸 중 2칸을 고른다.
   - 한 플레이어는 반드시 **서로 다른 2칸**을 골라야 한다. 같은 칸을 두 번 고를 수 없다.
   - **동시에, 서로 비공개로** 고른다.
   - **같은 칸을 양쪽이 모두 고를 수 있다** (먼저 고른 사람이 가져가는 방식 아님).
   - 30초 안에 2장을 다 고르지 못한 플레이어는 **패배**한다.
   - **선택 단계에서는 보드 카드의 앞면을 볼 수 없다.** 자신이 고른 칸도 결과가 확정되기 전까지 앞면을 보여주지 않는다 (어느 칸을 골랐는지만 표시).
5. **공개와 판정**: 각자 고른 2장 + 공유 카드 3장 = **정확히 5장**으로 족보를 만들어 비교한다.
6. **결과 화면**: 플레이어와 컴퓨터 각각의 선택 카드 2장, 최종 족보, 승패를 함께 보여준다.
   - **시간 초과 패배 때도 결과 화면을 보여준다.** 컴퓨터의 선택 2장과 족보는 공개한다. 플레이어는 시간 안에 고른 카드(0~1장)까지만 표시하고, 결과는 "시간 초과 패배"로 표시한다.

## 3. 족보와 비교

- 텍사스 홀덤 족보를 따른다 (높은 순):
  스트레이트 플러시(로열 포함) > 포카드 > 풀하우스 > 플러시 > 스트레이트 > 트리플 > 투페어 > 원페어 > 하이카드
- **키커까지 포함한 정확한 강도**로 비교한다. 같은 원페어라도 페어 랭크, 그다음 남은 카드를 높은 순으로 차례로 비교한다.
- **문양(suit) 간 우열은 없다.**
- A는 기본적으로 가장 높은 카드. 단, **A-2-3-4-5(휠)는 5 하이 스트레이트**로 가장 낮은 스트레이트이다.
- 구현 권장: 족보를 `[등급, 비교용 랭크1, 랭크2, …]` 형태로 만들어 사전순 비교.

## 4. 무승부와 재대결

- 키커까지 모두 같으면 **무승부**.
- 무승부면 **새 기억 카드 16장과 새 공유 카드 3장**으로 처음부터 다시 진행한다 (암기 60초 포함, 매번 동일).
- **승부가 날 때까지** 반복한다.

## 5. 컴퓨터 AI 난이도

- 가능한 선택은 C(16,2) = **120개 조합**. 각 조합을 공유 카드 3장과 합쳐 족보를 평가한다.
- 120개를 **키커 포함 강도순으로 정렬**한 뒤 구간을 나누고, 해당 구간에서 **무작위로 하나**를 고른다.

| 난이도 | 기본 구간  | 조합 수 (120개 기준) |
| ------ | ---------- | -------------------- |
| 상     | 상위 30%   | 36개                 |
| 중     | 그다음 40% | 48개                 |
| 하     | 하위 30%   | 36개                 |

- 비율은 **설정값**으로 둔다 (보드에 따라 체감 난이도가 달라서 조정 가능해야 함).
- **구간 크기 계산**:
  - 상 = `Math.round(120 × 상 비율)`
  - 하 = `Math.round(120 × 하 비율)`
  - 중 = 120 − 상 − 하 (나머지 전부)
- **설정 검증**: 아래 중 하나라도 어기면 **설정 에러**로 처리한다. 비율 합에 대한 조건은 따로 두지 않는다.
  - 상 비율과 하 비율은 각각 0 초과 1 미만
  - 반올림 후 상·중·하 세 구간이 모두 1개 이상 (예: 상 0.5 + 하 0.499 → 상 60, 하 60, 중 0 → 에러)
- **정렬과 자르기**:
  1. 120개 조합을 칸 인덱스 `i < j` 오름차순으로 나열한다: (0,1), (0,2), …, (0,15), (1,2), …, (14,15).
  2. 강도 **내림차순으로 안정 정렬**(stable sort)한다. 강도가 같은 조합은 1의 나열 순서를 유지한다.
  3. 앞에서부터 상 → 중 → 하 구간 크기만큼 자른다. 구간 경계에서 강도가 같은 조합도 이 순서대로 그대로 자른다 (별도 처리 없음).
- 컴퓨터는 카드를 모두 아는 상태로 계산한다. 컴퓨터는 시간 초과로 지지 않는다.
- AI 코드는 `packages/engine/src/ai.ts` (순수 로직).

## 6. 구현상 결정 사항

- 싱글 플레이에서는 카드 데이터가 브라우저에 있어도 된다 (개발자 도구로 볼 수 있어도 허용).
- 멀티 플레이 단계에서는 서버가 카드를 독점하고, 암기 단계 후 클라이언트에 카드 앞면을 보내지 않는다 (지금은 구현하지 않음).

## 7. 아직 정하지 않은 것 (구현 전에 사용자에게 확인)

- 멀티 플레이에서 양쪽이 모두 시간 초과한 경우의 처리
